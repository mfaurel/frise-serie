## Parallax Layer Specification

This is the core design contract for Phase 2. Three layers, three speeds.

### Layer 1 — Era Background (slow, 0.3× scroll speed)

**Purpose:** Immersive fresco depth. Backgrounds drift backward as user scrolls forward.

**Implementation:**
```
bgX = useTransform(scrollXProgress, [0, 1], [0, -(TOTAL_WIDTH * zoom * 0.7)])
```

> CORRECTION from existing code: current Timeline.tsx uses `0.4` multiplier which produces ~0.6× speed.
> Phase 2 must change this to `0.7` to achieve the specified 0.3× background speed.
> At 0.3× speed: background moves 0.3px for every 1px the user scrolls.
> Formula derivation: offset = TOTAL_WIDTH × zoom × (1 - targetSpeed) = TOTAL_WIDTH × zoom × 0.7

**prefers-reduced-motion:** When `useReducedMotion()` returns `true`, set `bgX` to a static `0` —
the era band still renders at full width with no transform applied.

**will-change:** Do NOT apply `will-change: transform` to the background layer div. The background
is one large element — GPU promotion is automatic via Framer Motion's `motion.div`. Explicit
`will-change` on the wrapper would create an unnecessary composite layer at 100% of viewport area.

**Texture approach:** Phase 2 delivers texture via CSS `background-image` SVG noise overlaid on
the gradient. Each era band gets a subtle grain pattern:
```css
background-image:
  url("data:image/svg+xml,..."),   /* SVG noise/grain — inline, no external fetch */
  linear-gradient(135deg, {era.gradient[0]}22, {era.gradient[1]}44);
background-blend-mode: overlay;
background-size: 200px 200px, 100% 100%;
```
The SVG noise pattern is a 200×200 inline SVG with `feTurbulence` baseFrequency `0.65` — this
produces a fine paper/parchment grain that reads as "illustrative texture" without being a
distinct illustration. All eras use the same noise pattern; the era gradient color handles visual
distinction. The noise opacity is controlled by setting the SVG fill to `rgba(255,255,255,0.03)`.

No external image assets. No `<img>` tags. No `next/image` for era backgrounds.

### Layer 2 — Time Axis (1× scroll speed, no parallax)

**Purpose:** Ground truth reference — the axis is the fixed measuring stick users orient to.

**Implementation:** The axis `<div>` is a standard absolutely-positioned element inside the
scrollable inner track. It has NO `motion.*` transform — it scrolls at native 1:1 with the
container, anchoring the experience.

**Axis line:** 1px horizontal rule at `top: 48` from container top, `bg-stone-600/60`.

**Tick marks:**
- Every `tickInterval` years (adaptive to zoom: 100y / 50y / 25y / 10y)
- Century tick: 16px tall (`h-4`), `bg-stone-400`
- Non-century tick: 8px tall (`h-2`), `bg-stone-600`
- 500-year tick: same height as century but labeled in amber-500

**Year labels:** Only on century ticks. Font-mono, 11px. 500-year labels: 13px, bold, amber-500.

### Layer 3 — Show Card Track (fast, >1× scroll speed)

**Purpose:** Cards appear to float in the foreground — closer to the user than the axis.

> Phase 2 does not implement show cards (Phase 3 scope). However, the card track layer must be
> architecturally present so Phase 3 can insert cards without restructuring the parallax DOM.

**Implementation:**
```tsx
// Card track wrapper — no Motion transform in Phase 2 (cards absent)
// Phase 3 will add: cardX = useTransform(scrollXProgress, [0, 1], [0, TOTAL_WIDTH * zoom * 0.15])
// meaning cards move 1.15× scroll speed — slight forward parallax
<div className="absolute inset-0 pointer-events-none" data-layer="card-track">
  {/* Phase 3 inserts show cards here */}
</div>
```

The `data-layer="card-track"` attribute serves as a mount point contract for Phase 3.

**prefers-reduced-motion:** When motion is reduced, card track has no transform — cards render
at their computed `yearToPixel()` position with no parallax offset applied.

## Skeleton Loading Contract

**Target:** Era backgrounds + axis visible within 1 second on Lighthouse throttled mobile.

**Strategy:** Progressive enhancement — the SSR shell (Server Component) renders the skeleton
immediately; client hydration replaces it with the animated parallax version.

### Skeleton structure

```
<div role="status" aria-label="Loading timeline…" className="animate-pulse">
  {ERAS.map(era => (
    <div key={era.id} style={{ left: yearToPixel(era.yearStart), width: … }}
         className="absolute top-0 bottom-0 bg-stone-800 border-r border-stone-700" />
  ))}
  <div className="absolute h-px bg-stone-700" style={{ top: 48, left: 0, right: 0 }} />
  <span className="sr-only">Chargement de la frise… / Loading timeline…</span>
</div>
```

The skeleton uses ERAS data which is statically imported — zero network fetches required for the
skeleton render. This guarantees sub-1-second first paint.

**Transition:** When the client-side `Timeline` component hydrates, the skeleton fades out via
`animate-fade-in` on the Timeline wrapper (`animation: fadeIn 0.4s ease-out` already in
`tailwind.config.ts`). No layout shift — skeleton and Timeline share identical era band
`left`/`width` values from `yearToPixel()`.

## Interaction Contracts

### Horizontal scroll

| Surface | Required CSS | Reason |
|---------|-------------|--------|
| `.timeline-scroll` container | `touch-action: pan-x` | iOS Safari: prevents vertical scroll interference |
| `.timeline-scroll` container | `overflow-x: auto; overflow-y: hidden` | Already set — confirm remains |
| `.timeline-scroll` container | `scroll-behavior: auto` (NOT smooth) | Smooth scroll fights Framer Motion transform |

`touch-action: pan-x` MUST be applied as an inline style or a dedicated CSS class on the
scrollable container div. Tailwind does not have a direct `touch-action: pan-x` utility in v3 —
use `style={{ touchAction: 'pan-x' }}` on the element.

### Keyboard navigation

| Key | Behavior | Existing? |
|-----|----------|-----------|
| `ArrowRight` | Scroll right 120px | Yes (Timeline.tsx) |
| `ArrowLeft` | Scroll left 120px | Yes (Timeline.tsx) |
| `Tab` | Focus to zoom controls | Inherit — no change |

Phase 2 does not add new keyboard interactions.

### Zoom controls

| Control | Behavior |
|---------|----------|
| `−` button | Decrease zoom by 0.25, min 0.5 |
| `+` button | Increase zoom by 0.25, max 4 |
| Display | `{zoom * 100}%` in stone-400, 10px mono |

Zoom control visual: `bg-stone-900/80 backdrop-blur border border-stone-700 rounded-lg` — existing,
confirm unchanged.

### prefers-reduced-motion

Apply `useReducedMotion()` from Framer Motion at the top of `Timeline.tsx`:

```tsx
const shouldReduceMotion = useReducedMotion();

// Background layer:
const bgX = shouldReduceMotion
  ? 0
  : useTransform(scrollXProgress, [0, 1], [0, -(TOTAL_WIDTH * zoom * 0.7)]);
```

When reduced motion is active:
- Background layer renders at pixel position 0 — no transform
- Era bands are fully visible (same width/position, no drift)
- Axis renders normally
- Zoom still works (zoom is not motion — it is a layout scale change)

## Performance Constraints (Non-Negotiable)

These flow directly from REQUIREMENTS.md UX-04 and CLAUDE.md critical constraints:

1. **GPU layer budget:** `will-change: transform` MUST NOT be set on the era background `motion.div`
   or on any era band child div. The parallax effect relies on Framer Motion's transform; the GPU
   layer is promoted automatically by the browser when a transform is actively animating. Explicit
   `will-change` on 9 era divs + 1 background layer would create 10 stacking contexts at
   simultaneous composite layers — prohibited.

2. **Scroll position never enters React state:** The `currentYear` indicator update uses
   `el.scrollLeft` read directly in a passive scroll listener — this value is stored in React state
   for the year pill display only, NOT for parallax calculations. The `scrollXProgress` Motion
   value drives all transforms. This boundary is already respected in Timeline.tsx — Phase 2 must
   not regress it.

3. **touch-action: pan-x:** Must be set on `.timeline-scroll` div before Phase 2 ships. This is
   invisible in DevTools emulation and only caught on physical iOS Safari hardware. Absence causes
   `pointercancel` on diagonal swipe, breaking the parallax scroll.

4. **1-second skeleton budget:** `TimelineSkeleton` must use only statically-imported ERAS data.
   No `useEffect`, no `fetch`, no dynamic imports in the skeleton path.
