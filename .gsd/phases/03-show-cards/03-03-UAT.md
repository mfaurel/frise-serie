# S03: Narrative span bars and constellation lines — UAT

**Milestone:** M003
**Written:** 2026-07-30T21:49:39.500Z

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: All S03 acceptance criteria (SVG layer presence, span-bar rendering, constellation-line rendering, hover opacity change) are covered by automated Playwright tests in `e2e/timeline-s03.spec.ts` running against the live dev server, exercising real DOM attributes and hover state transitions without manual interaction.

## Preconditions

- Dev server running on `http://localhost:3000` (`npm run dev`)
- Chromium installed via `npx playwright install chromium`
- `e2e/timeline-s03.spec.ts` present in the repository (S03 describe block appended to existing file)

## Smoke Test

`npx playwright test e2e/timeline-s03.spec.ts --project=chromium` — all 9 tests pass in under 30s.

## Test Cases

### 1. Constellation SVG layer is present

1. Navigate to `http://localhost:3000`
2. Wait for page load
3. **Expected:** `[data-testid="constellation-layer"]` is attached to the DOM (`toBeAttached()` passes — `toBeVisible()` is intentionally avoided because `pointerEvents:none` on the SVG causes Playwright to consider it not visible even when rendered)

### 2. At least one span-bar element is rendered

1. Navigate to `http://localhost:3000`
2. Query all `[data-testid="span-bar"]` rect elements
3. **Expected:** Count ≥ 1 (shows with non-null `narrativeYearEnd` produce bars — Spartacus, Rome, Britannia, Domina, etc.)

### 3. At least one constellation-line element is rendered

1. Navigate to `http://localhost:3000`
2. Query all `[data-testid="constellation-line"]` path elements
3. **Expected:** Count ≥ 1 (Spartacus/Rome/Britannia share the `peplum` genre → multiple connecting lines)

### 4. Hovering a show card changes constellation line opacity

1. Navigate to `http://localhost:3000`
2. Read `opacity` attribute of any `[data-testid="constellation-line"]` before hover — expected < 0.5 (baseline 0.15)
3. Read `data-show-id` from first `[data-testid="span-bar"]` to identify show (e.g., `spartacus`)
4. Hover the first `[data-testid="parallax-cards"] > div` wrapper
5. **Expected:** `[data-show-a="spartacus"], [data-show-b="spartacus"]` path has `opacity="0.9"` (active tier, verified via `toHaveAttribute` with auto-retry)

## Edge Cases

### pointerEvents:none does not block card hover events

1. Hover a show card that is visually overlapped by the SVG overlay
2. **Expected:** `onMouseEnter` fires on the card wrapper correctly; `hoveredShowId` state updates; constellation lines change opacity as expected

### Shows without narrativeYearEnd produce no span bar

1. Inspect `[data-testid="span-bar"]` elements in DevTools
2. **Expected:** No `<rect>` exists for shows where `narrativeYearEnd` is null in `data/shows.ts`

## Failure Signals

- 0 `[data-testid="span-bar"]` elements: `ConstellationLayer` not mounted, or all shows have null `narrativeYearEnd`
- 0 `[data-testid="constellation-line"]` elements: `computeConstellationSegments` found no shared genres — check `genres` arrays in `data/shows.ts`
- Hover opacity stays at 0.15: `onMouseEnter`/`onMouseLeave` not wired on card wrappers, or `hoveredShowId` state not propagated to `ConstellationLayer`
- TypeScript errors after component changes: `findEraForYear` is duplicated locally in `ConstellationLayer.tsx` — if era type changes, both copies must be updated

## Not Proven By This UAT

- Exact pixel coordinates of span bars (covered by unit tests in `tests/constellation-lines.test.ts`)
- Correct era color per show (covered by unit tests)
- Behavior under window resize (not tested — positions computed once at mount)
- Mobile touch / hover on touch devices (not tested)
- Screen reader accessibility of the SVG overlay (not tested)

## Notes for Tester

The S03 constellation tests live in a `describe` block appended to `e2e/timeline-s03.spec.ts`, which also contains 5 parallax tests from prior slices. All 9 tests must pass. `toBeAttached()` is intentional — see T03 key decision above. The hover anchor is derived dynamically from the first `data-show-id` span-bar attribute, so the test is resilient to future show-data reordering.
